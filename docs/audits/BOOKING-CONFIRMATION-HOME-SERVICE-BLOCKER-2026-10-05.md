The existing `bookings.status` CHECK already includes `pending_crm_confirmation`; no new enum value is indicated by repository source. Its old column comment links that status to _paid_ online bookings, which conflicts with the new payment-independent meaning and would need correction alongside the function. The BKG3 order status derives from child booking lines. There is no stored order review status. The canonical creation RPC is the blocker: changing only TypeScript after it returns would expose an already-confirmed booking between writes, break the atomic creation contract, and leave a failure/retry window. Changing the shared RPC to always insert pending would also change direct CRM creation. A function-definition migration is therefore required even if no table or enum schema change is needed.

## Proposed transition contract for separately authorized work

| Origin              | Review status at creation                              | Payment status at creation                                                | Service progress                    | Allowed next review transition                                                                            |
| ------------------- | ------------------------------------------------------ | ------------------------------------------------------------------------- | ----------------------------------- | --------------------------------------------------------------------------------------------------------- |
| Online spa          | `pending_crm_confirmation`                             | `unpaid` for current pay-at-spa path; later posted payment is independent | `not_started`                       | Privileged, branch-scoped confirmation to `confirmed`, or existing authorized rejection/cancellation path |
| Online Home Service | `pending_crm_confirmation`                             | Same independent payment rule                                             | `not_started`                       | Privileged CRM confirmation to `confirmed`; assignment/routing and trip progress remain operational steps |
| CRM spa             | `confirmed` under current authorized in-house contract | Derived from actual tender/allocations; may remain unpaid                 | `not_started` or explicitly arrived | Existing service lifecycle                                                                                |
| CRM Home Service    | `confirmed` under current authorized in-house contract | Same independent rule                                                     | `not_started`                       | Existing assignment and trip workflow without a second booking approval                                   |

`cancelled`, `no_show`, `in_progress`, and `completed` remain separate canonical service states. A payment write must not change review status. Confirmation must not create a payment.
