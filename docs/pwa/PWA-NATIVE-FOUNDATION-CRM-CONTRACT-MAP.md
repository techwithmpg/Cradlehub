# CRM / Front Desk Staff PWA contract map

Recorded before CRM mobile implementation on `stage/staff-pwa-native-foundation-crm`, based on Driver parent `2585a18fd048311f35f4236e0c805aff171eb525`.

The 2026-10-12 owner CRM role brief explicitly permits a compact, repository-supported branch booking view for Front Desk. This is narrower than desktop CRM administration. Where older C4 personal-work wording conflicts with this read-only branch view, the latest explicit owner instruction controls; booking mutations and broader CRM modules remain outside this stage.

| Concern                       | Repository authority and current behavior                                                                                                                                                                                                                                                                                                                                 | CRM mobile decision                                                                                                                                            |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Identity and roles            | `getStaffPwaContext()` resolves an authenticated, active, branch-assigned staff row. `resolveStaffPwaOperationalGroup()` admits CRM/front-desk aliases and generic operational staff, excluding owner/management/marketing and routing provider, utility, and driver separately. `canManageBookings()` grants actual CRM/front-desk booking authority, not generic staff. | Use the shared context for reads. Show booking data only when `canManageBookings()` allows it. Generic operational staff retain task/notice/attendance access. |
| Route and navigation          | Canonical `/staff/` uses `Today · Work · Scan · Notices · More`; `/staff/work` already reads booking/workflow/attendance attention. `/staff/scan` is the shared attendance/public-code scanner.                                                                                                                                                                           | Keep the five destinations and scanner meaning. Build native CRM Today and Work within `/staff/`.                                                              |
| Booking reads                 | `getStaffWork()` loads branch-scoped booking attention, CRM workflow tasks, and attendance exceptions. CRM bookings desktop uses `getCrmBookingsCommandCenterRows()` and branch-scoped `getFrontDeskContext()`. Booking/customer/service relations are established in `getWeekSchedule()`.                                                                                | Add a bounded, branch-scoped mobile booking read model with customer name and service only. Display service status read-only. Never cache customer names.      |
| Booking mutation and creation | CRM actions use `getCrmActionsContext()` and the existing booking operations/booking wizard; the wizard also depends on service, attendee, payment, location, assignment, and branch contracts.                                                                                                                                                                           | No new mobile booking mutation or second creation engine. Current desktop CRM remains the action surface.                                                      |
| Customers                     | CRM customer actions and workspace support lookup and editing. Customer records contain phone, notes, and other sensitive information; there is no canonical Staff mobile customer detail contract.                                                                                                                                                                       | No new mobile customer search, edit, or PII cache.                                                                                                             |
| Payment and cash              | `confirmBookingPaymentAction()`, Cash Flow actions, and session handover have separate payment/allocation/drawer contracts. The checkout mock is not a repository contract. Closed booking payment protection is a stabilization concern.                                                                                                                                 | No mobile payment, checkout, Cash Flow, financial totals, or reports.                                                                                          |
| Attendance and scanner        | `/staff/attendance` is the staff attendance view. `/staff/scan` dispatches known attendance/public codes and activation targets to their existing server owners; it does not implement customer booking QR checkout.                                                                                                                                                      | Preserve and label as attendance scan. No new scanner payloads.                                                                                                |
| Notices                       | `getStaffNotices()` scopes by branch, workspace, recipient, current assignment and entity state. `markStaffNoticeRead()` and attendance response actions revalidate server authority.                                                                                                                                                                                     | Retain notices and existing two server actions.                                                                                                                |
| Branch and source of truth    | Authenticated staff profile and branch are server resolved; booking/workflow/notice reads use that branch. CRM desktop authority is separate from Staff PWA identity.                                                                                                                                                                                                     | No browser-supplied branch authority, no client-authoritative status or financial state.                                                                       |
| Safe memory                   | Shared `StaffSafeMemoryProvider` stores only counts/labels and small filter preferences in memory; no persistent storage.                                                                                                                                                                                                                                                 | Add CRM count snapshots and work filter, keyed to staff identity. No booking rows, customer PII, money, QR, or permissions.                                    |

The inherited Utility `markRoomReady()` ownership defect is outside this role branch and remains a required final integration correction.
Cancelled booking payment/finalization protection also remains a final integration stabilization requirement; this CRM role branch adds no payment path.
