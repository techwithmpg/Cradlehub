# Master Sheet Stage 1D-AUTH — production read-only Google authentication design

**Evidence label:** REPOSITORY-RECORDED WORKING EVIDENCE

**Target:** CradleHub Web

**Branch and inspected HEAD:** `stage/master-sheet-readonly-projection` at `0cd1a8741fc44300c1cb5006d03cb2ddf3affc30`

**Scope:** architecture and security inspection only. No production Sheet read, credential inspection, IAM or Vercel change, runtime QA, merge, or deployment.

Labels below distinguish repository evidence and official platform behavior (**VERIFIED FACT**), the proposed design (**RECOMMENDATION**), and choices or live prerequisites that require the owner/platform administrators (**PROJECT DECISION REQUIRED**). A supported platform pattern does not prove that CradleHub's Google Cloud or Vercel settings permit it.

## 1. Current architecture and blocker

**VERIFIED FACT:** [`SheetTokenProvider`](../../src/lib/integrations/google-sheets/sheet-reader.ts) supplies a bearer token to the `server-only` reader. The reader has a fixed workbook ID by default, makes Google Sheets API `GET` requests with `cache: "no-store"`, and returns bounded unavailable states. [`sheet-review-service.ts`](../../src/lib/integrations/google-sheets/sheet-review-service.ts) checks the current Supabase user for super-admin or active Owner authority **before** constructing the reader. The [`/crm/master-sheet` route](../../src/app/(dashboard)/crm/master-sheet/page.tsx) returns `notFound()` on forbidden access and passes only the projected read model to the client view. No public Sheet API route exists.

**VERIFIED FACT:** [`sheet-adc-token-provider.ts`](../../src/lib/integrations/google-sheets/sheet-adc-token-provider.ts) accepts only the expected impersonated identity, requests `https://www.googleapis.com/auth/spreadsheets.readonly`, and throws when `NODE_ENV === "production"`. The Review service currently always selects that local provider, so a production build fails closed into the Review unavailable state. Stage 1B proved this **local** keyless path, not a deployed one. `google-auth-library` is pinned at `11.1.0`; `@vercel/oidc` is not a dependency. Other repository Google uses include a public sign-in client ID and a server Maps API key; neither is a Sheet credential path. `.gitignore` excludes `.env*` except `.env.example`, `.vercel`, and `*.pem`. [`vercel.json`](../../vercel.json) contains only a cron definition; [`next.config.ts`](../../next.config.ts) has no Google credential configuration. These observations do not reveal the live Vercel OIDC, Google IAM, or workbook-sharing state.

**OWNER-SUPPLIED CONSTRAINT:** Service-account key creation is blocked by organization policy. This design preserves that policy. Google documents Workload Identity Federation as a keyless alternative and documents the key-creation constraint; it does not require disabling the constraint. [Google WIF overview](https://docs.cloud.google.com/iam/docs/workload-identity-federation), [service-account credentials](https://docs.cloud.google.com/iam/docs/service-account-creds).

## 2. Official-platform findings

**VERIFIED FACT:** Vercel supports OIDC federation to Google Cloud on all plans. Functions receive a signed OIDC assertion in their request context; Vercel documents a GCP Workload Identity Federation setup and a `google-auth-library` external-account client with a subject-token supplier and service-account impersonation. The production/preview OIDC assertion lasts one hour, with Vercel caching issuance for at most 45 minutes. Its claims include issuer, audience, project/team identity, environment, and subject. [Vercel GCP guide](https://vercel.com/docs/oidc/gcp), [OIDC overview](https://vercel.com/docs/oidc), [OIDC claims](https://vercel.com/docs/oidc/reference).

**VERIFIED FACT:** Google Security Token Service can exchange an OIDC assertion for a federated credential; an exact external principal may be granted `roles/iam.workloadIdentityUser` **on one service account** to obtain a short-lived impersonated access token. Google recommends a provider-specific audience and narrow attribute conditions for multi-tenant issuers. An impersonated service-account access token defaults to one hour and can be requested for a shorter lifetime; it has no refresh token and cannot be instantly revoked after minting. [Google WIF configuration](https://docs.cloud.google.com/iam/docs/workload-identity-federation-with-other-providers), [WIF security practices](https://docs.cloud.google.com/iam/docs/best-practices-for-using-workload-identity-federation), [access-token API](https://docs.cloud.google.com/iam/docs/reference/credentials/rest/v1/projects.serviceAccounts/generateAccessToken), [token types](https://cloud.google.com/docs/authentication/token-types).

**VERIFIED FACT:** `spreadsheets.readonly` authorizes read operations but is **not a one-workbook scope**; it covers spreadsheets that the identity can access. `spreadsheets.values.get` accepts this scope. Google Drive's `reader` role corresponds to Viewer file access, including for service accounts. The workbook ACL and the fixed reader target, not the OAuth scope alone, must limit which workbook is reachable. [Sheets scopes](https://developers.google.com/workspace/sheets/api/scopes), [values.get](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets.values/get), [Drive roles](https://developers.google.com/workspace/drive/api/guides/ref-roles).

**VERIFIED FACT:** Next.js keeps non-`NEXT_PUBLIC_` environment variables server-side and can read them at request time in a dynamic server route; `NEXT_PUBLIC_` values are inlined into browser JavaScript. `server-only` prevents accidental client imports, but values passed as Client Component props still reach the browser. Vercel environment variables are scoped by Production/Preview/Development and are available at build and function runtime; changes apply to new deployments. Current Vercel configuration UI distinguishes readable **Config** from non-readable **Secret** values. [Next.js environment guidance](https://nextjs.org/docs/app/guides/environment-variables), [Next.js data security](https://nextjs.org/docs/app/guides/data-security), [Vercel environments](https://vercel.com/docs/environment-variables), [Vercel Config/Secret change](https://vercel.com/changelog/environment-variables-now-use-config-and-secret-types).

## 3. Options considered

| Option | Security and fit | Secrets, lifecycle, operations, and cost | Decision |
| --- | --- | --- | --- |
| **A. Vercel OIDC → Google WIF direct principal** | Keyless and short-lived, but direct federated-principal access to this Google **Workspace file ACL** is not established by the inspected documentation. Google generally recommends direct access to supported Google Cloud resources; that does not prove direct Sheets file sharing works. | No Google key; WIF provider, claim policy, STS calls, Google/API quotas and audit operations. | Do not assume it works for this workbook. |
| **B. Vercel OIDC → Google WIF → dedicated service-account impersonation** | Official Vercel-to-GCP pattern; a Google service-account identity can receive Viewer access to the single workbook. Exact production claims and narrow IAM grant control impersonation. Final access token is short-lived and Sheets read-only. | No stored Google key or refresh token. Requires OIDC, WIF pool/provider, IAM Credentials and STS APIs, a service account, workbook Viewer sharing, monitoring, and incident runbook. Platform/API quota and billing impact must be checked by administrators; no cost figure was measured. | **Recommended, conditional on live policy and integration checks.** |
| **C. Service-account JSON key in Vercel** | Technically common, but a long-lived exportable private key would expand exposure and conflicts with the stated organization policy. | Secret at rest, key creation/rotation/revocation, recovery, accidental logging/build exposure; higher maintenance and incident cost. | Rejected. Do not weaken policy. |
| **D. OAuth user refresh token or an intermediary Google-hosted broker** | A user refresh token creates a long-lived user credential with potentially broader file access. A broker can remain keyless, but introduces a separately deployed service, trust path, monitoring, and another outage mode. | Refresh-token storage/rotation or broker infrastructure and operating cost; both add complexity. | No current reason to prefer either. Reassess only if B is proven unavailable. |

## 4. Recommended boundary and provider contract

**RECOMMENDATION:** Keep the existing reader unchanged. A future `server-only` production provider should implement `SheetTokenProvider.getAccessToken(): Promise<string>` and return only a short-lived **impersonated service-account** OAuth access token whose final requested scope is exactly `https://www.googleapis.com/auth/spreadsheets.readonly`. At request time, and only after the existing Owner/super-admin check, it should obtain the Vercel OIDC assertion, exchange it through Google STS, impersonate the designated reader service account via IAM Credentials, and return the access token to the existing reader. It must not accept a spreadsheet ID, scope, endpoint, service-account email, or OIDC assertion from the browser. Its Google STS/IAM endpoints and target identity must come from trusted fixed configuration, not an unvalidated credential JSON or request parameter. The `google-auth-library` authors warn that external-account credential URLs are not validated by the library. [Vercel GCP guide](https://vercel.com/docs/oidc/gcp), [Google auth library security note](https://github.com/googleapis/google-auth-library-nodejs/blob/main/README.md).

**RECOMMENDATION:** Select providers by explicit deployment environment, not `NODE_ENV` alone: LOCAL development continues using the existing guarded ADC provider; only a verified `VERCEL_ENV=production` function may select the production provider. Missing, Preview, custom, or ambiguous environment/configuration must fail closed to sanitized unavailable. OIDC acquisition must occur inside the request, never at module import or build time. Keep the current production guard until the new provider and selector are separately approved and tested. Vercel documents `VERCEL_ENV` and environment-specific variables; its OIDC helper documents request-scoped access. [Vercel system variables](https://vercel.com/docs/environment-variables/system-environment-variables), [OIDC reference](https://vercel.com/docs/oidc/reference).

**PROJECT DECISION REQUIRED:** The Vercel GCP guide demonstrates `@vercel/oidc` with an external-account client, but this repository has not installed the helper or tested that helper inside this specific Next.js 16 Server Component on the pinned `google-auth-library@11.1.0`. A later authorized implementation must verify the exact library APIs, Node.js function packaging, request-context token access, custom audience handling, and final `generateAccessToken` scope before claiming compatibility. An alternate narrow server route is a design fallback only if the current page context cannot receive the Vercel assertion; it would need the same Owner authorization and must never return the token.

## 5. Google IAM and workbook access

**RECOMMENDATION:** Use a dedicated production Sheet-reader service account with **no user-managed key** and no broad project data roles. Enable only the APIs needed for WIF/STS, service-account impersonation, and Sheets. Create a WIF pool/provider for the Vercel team issuer and use the provider URL as the OIDC audience. Map `google.subject` from the signed Vercel subject and set an attribute condition that binds the immutable Vercel team/project IDs and `environment=production`; grant `roles/iam.workloadIdentityUser` on this service account only to the exact production principal. Do not grant an entire pool, all previews, or the project Owner/Editor role. The generic Storage Admin role in Vercel's example is for its sample resource and is **not** appropriate here. [Vercel GCP guide](https://vercel.com/docs/oidc/gcp), [Google WIF best practices](https://docs.cloud.google.com/iam/docs/best-practices-for-using-workload-identity-federation).

**RECOMMENDATION:** Have the workbook owner grant this service-account email **Viewer/reader on CRADLE MAINSHEETS only**. Do not grant shared-drive or parent-folder membership that exposes other files, and do not enable domain-wide delegation. Verify the effective file permission and sharing policy before any live test. Keep the fixed workbook ID in server code; a server-held ID is routing configuration, not a secret or a substitute for Google file permissions. The reader's range/tab selection remains server-side. [Drive sharing roles](https://developers.google.com/workspace/drive/api/guides/ref-roles), [Sheets scope boundary](https://developers.google.com/workspace/sheets/api/scopes).

## 6. Vercel configuration and secret boundary

**RECOMMENDATION:** Configure the **Production** environment of the exact Vercel project only. Non-secret server-only Config identifiers would include the Google project number, WIF pool/provider IDs, provider audience, exact reader service-account email, and expected Vercel team/project identifiers. They must be validated against an approved allowlist in the provider and must have no `NEXT_PUBLIC_` prefix. The Vercel OIDC assertion is issued by Vercel at function request time; do **not** store it as a static environment variable. Store no Google key, JSON credential, user refresh token, STS token, or impersonated access token in Vercel variables, repository files, build output, cookies, logs, or client props. The non-secret identifiers are available to the Vercel build environment but should only be read by the server-only provider at runtime; no secret-valued variables are proposed. [Vercel environments](https://vercel.com/docs/environment-variables), [Next.js environment behavior](https://nextjs.org/docs/app/guides/environment-variables).

| Material | Classification and location | Lifetime / browser boundary |
| --- | --- | --- |
| Provider IDs, audience, target service-account email | Non-secret identifiers; Vercel Production Config, server-only provider | No token lifetime; do not put in `NEXT_PUBLIC_` or Client Component props. |
| Vercel OIDC assertion | Ephemeral secret supplied to the Function request | About one hour; never serialize, log, persist, or forward to browser. |
| Google STS and impersonated access tokens | Ephemeral secrets in server function memory only | Impersonated token default one hour; request a shorter lifetime if library support and latency allow. No durable token cache or Sheet-content cache. |
| Workbook ID | Existing fixed server reader target | Not an authorization secret; never accept a browser-supplied replacement. |

**RECOMMENDATION:** Production credentials and workbook sharing should **not** be enabled for general Preview deployments. If Preview QA is later authorized, create a distinct preview WIF principal, service account, and **test workbook**, with separate branch-scoped configuration and no production workbook access. Preview builds also use `NODE_ENV=production`, so `NODE_ENV` alone cannot enforce this separation. Vercel supports environment and branch-specific configuration. [Vercel environments](https://vercel.com/docs/environment-variables), [Vercel OIDC claims](https://vercel.com/docs/oidc/reference).

## 7. Owner authorization, threats, and failure behavior

**RECOMMENDATION:** Google authentication proves only that the CradleHub server can read the workbook. It must never replace the current per-request Supabase `getUser()` plus super-admin/active-Owner check. The authorization check must remain before OIDC/STS acquisition and Google reads; an unauthorized or failed lookup returns no Sheet model. The server sends only the minimized read model to the client. [Current service](../../src/lib/integrations/google-sheets/sheet-review-service.ts), [Next.js data security](https://nextjs.org/docs/app/guides/data-security).

| Threat or failure | Proposed control |
| --- | --- |
| OIDC/Google token leakage through browser, build, cookies, or logs | Server-only provider, no `NEXT_PUBLIC_`, no client props or API token response, no credential values at module/build time, sanitized timing/status logs. Inspect built client output in an authorized implementation review. |
| Stolen OIDC token or token reuse | Provider-specific audience; exact signed production team/project/environment claims; short lifetime; do not persist. Limit service-account impersonation to the exact principal. |
| Scope escalation or arbitrary Sheet access | Hardcode final `spreadsheets.readonly` scope and fixed reader workbook; test `generateAccessToken` scope. Give service account Viewer access only to the intended file; no broad Drive scope, parent/shared-drive access, or domain-wide delegation. |
| Untrusted STS or impersonation URL / SSRF-like redirection | Construct Google API URLs from fixed trusted domains and validated identifiers; do not load arbitrary external-account JSON or client-supplied spreadsheet IDs. |
| Preview accidentally reaching production Sheet | Production-only OIDC principal, Google attribute condition, production-only config and sharing; distinct preview identity/test workbook if later approved. Fail closed when `VERCEL_ENV` is missing or not production. |
| Unauthorized CRM user | Existing server-side Owner/super-admin authorization before provider/reader; navigation hiding remains secondary. |
| Google outage, revoked share/identity, missing config, invalid OIDC | Bounded unavailable state on Review only; no fallback to local ADC, keys, user OAuth, broader scope, or canonical CRM data. Record only sanitized phase/status timing. |

**VERIFIED FACT / LIMITATION:** [`next.config.ts`](../../next.config.ts) already sets a two-minute dynamic client-router stale time globally. This design adds no Sheet-content cache, but that existing setting may retain a previously authorized Review payload in a browser navigation history. The later security review should test sign-out/role-revocation behavior and decide whether the route needs a narrow cache-policy correction. This memo does not change it.

## 8. Rotation, revocation, implementation gate, and rollback

**RECOMMENDATION:** No Google private key requires rotation. Let Vercel rotate its OIDC signing keys; Google validates the provider's issuer/JWKS. Set the impersonated token lifetime to the shortest practical supported value, at most the normal one-hour default. Monitor Google STS/IAM Credentials failures, Sheets 403/429/5xx, and sanitized Review availability/latency without tokens or row data. Review the exact production principal, service-account grants, and workbook ACL periodically. To revoke, disable the WIF provider or remove the exact `roles/iam.workloadIdentityUser` grant and workbook Viewer permission; disable the Vercel OIDC trust if necessary. Previously minted tokens can remain valid until expiry, so revocation is not equivalent to instant token invalidation. [Google token types](https://cloud.google.com/docs/authentication/token-types), [Google WIF management](https://docs.cloud.google.com/iam/docs/manage-workload-identity-pools-providers).

**PROJECT DECISION REQUIRED before implementation:** (1) approve the keyless WIF/impersonation design and name the Google/Vercel administrators; (2) confirm organizational policy permits WIF pool/provider, IAM Credentials API, service-account impersonation, and one-workbook Viewer sharing; (3) approve reuse of the current local reader identity or a dedicated production identity (dedicated is recommended); (4) choose Production-only credential access and, separately, whether to authorize an isolated Preview test identity/workbook; (5) approve a later code/config/IAM change stage and its separate production test gate. The actual Vercel OIDC setting, Google claims, IAM roles, Sheet ACL, API enablement, quota/billing, and deployed package behavior were **not inspected**.

**Implementation scope if separately approved:** add and pin the Vercel OIDC helper only after compatibility verification; implement a server-only production `SheetTokenProvider` and explicit environment selector; preserve the local guard and reader; add unit/negative tests for subject/audience/scope/env failure, unauthorized-before-credential ordering, sanitized errors, and no browser leakage; perform a security review of the generated client bundle and cache behavior; then provision narrowly scoped IAM and Vercel Production identifiers in a controlled change. No new public Sheet endpoint is required by this design.

**Browser-QA path after implementation:** first identify a LOCAL or TEST/STAGING Supabase target and existing test Owner and ordinary-user identities; use the local ADC path or a separately approved preview identity bound to a test workbook; run the Stage 1D-QA viewport/auth/accessibility/network checks without mutations. Any production smoke test of the new credential path requires separate target-aware owner authorization. Local/Preview success is not production verification.

**Rollback:** revert the later provider-selection code and disable/remove the narrowly granted WIF principal or provider and workbook Viewer permission; the current local-only provider's production guard then leaves Review unavailable. No Sheet or Supabase data rollback is implied by this design-only document.
