# Stabilization Scope

## Objective

CradleHub stabilization will:

- preserve what works;
- identify what is broken;
- correct P0/P1 problems;
- simplify staff workflows;
- establish consistent UI rules;
- improve measured performance; and
- reach a stable, training-ready release.

It will not expand speculative product scope or introduce features merely because they are adjacent to a problem.

## Severity

| Severity | Meaning |
| --- | --- |
| P0 | Critical: data loss, security exposure, production outage, or unsafe operational behavior |
| P1 | High operational impact: materially incorrect, blocked, or misleading staff/customer workflow |
| P2 | Moderate impact or polish issue with a bounded workaround |
| P3 | Later improvement; not part of stabilization unless explicitly promoted |

## Scope rule

C0B establishes governance only. Individual defects, refactors, and release candidates are selected only after C2 diagnostics and C3 scope freeze.
